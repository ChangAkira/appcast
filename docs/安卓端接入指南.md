# 安卓端接入指南

目标：手机把「当前正在使用的应用」实时发给服务器，服务器推送到网页。

---

## 0. 先记下这三个值

| 项目 | 值 | 说明 |
|---|---|---|
| 服务器地址 | `http://39.96.193.209:4173` | 4173/tcp 已在阿里云安全组放行（见 §7） |
| 上报 Token | `6184f94a5eaa9fac6a0c3e7c` | 手机用，写进自动化 App / App 配置里 |
| 看板密钥 | `bPhCada64Off` | 人看，浏览器打开 `http://39.96.193.209:4173/?k=bPhCada64Off` |

> 三个值都来自 `server/config.json`，改完重启服务即可生效。换 Token = 换设备身份。服务器若显示「更新功能中」，是维护开关被放下了，手机上已配好的宏不用改，恢复后下一次切应用就会回来。

## 1. 上报协议（照抄即可）

**最简形式：一个 HTTP GET，带查询参数。**

```
GET http://39.96.193.209:4173/api/report?t=6184f94a5eaa9fac6a0c3e7c&pkg=com.tencent.mm
```

成功返回：

```json
{"ok":true,"device":"phone","app":"微信","changed":true}
```

### 参数表

| 参数 | 必填 | 说明 |
|---|---|---|
| `t` | ✅ | 上报 Token。也可放请求头 `X-Token: <token>` 或 JSON body 的 `token` 字段 |
| `pkg` | 建议 | 前台应用**包名**，如 `com.tencent.mm`。只发这个就够，服务器内置包名→中文名映射 |
| `name` | 可选，慎填 | 前台应用**显示名**，如 `微信`。⚠️ 见下方「中文怎么发」 |
| `screen` | 可选 | `on` / `off` / `lock`。用于息屏锁屏状态，不发的话息屏后会一直显示最后一个应用 |
| `ts` | 可选 | 手机侧毫秒时间戳，仅作日志参考，服务器以自己收到的时间为准 |

也接受 POST：`application/json`（`{"token":"...","pkg":"...","name":"..."}`）或 `application/x-www-form-urlencoded`（`t=...&pkg=...`）。

### ⚠️ 中文怎么发（这条最容易翻车，先看）

**只有「写在 URL 里的中文」有坑**：Node 的 HTTP 解析器不允许请求行出现未编码的非 ASCII 字节，`&name=微信` 会被直接拒成 **HTTP 400**，请求进不到业务逻辑。已经实测确认：

| 写法 | 结果 |
|---|---|
| `GET /api/report?...&name=微信`（原始中文在 URL） | ❌ 400，什么都不上报 |
| `GET /api/report?...&name=%E5%BE%AE%E4%BF%A1` | ✅ 200 |
| `POST` + body `name=抖音`（原始中文在正文） | ✅ 200，中文完好 |
| `POST` + JSON body `{"name":"淘宝"}` | ✅ 200，中文完好 |

所以按可靠性排序：

1. **只发 `pkg`，中文名交给服务器**（推荐，全是 ASCII，怎么发都不会错）。
2. 内置表没有的应用：往 `server/config.json` 的 `labels` 里加一行，`systemctl restart appcast` 生效（优先级高于手机发的 `name`）。
3. 一定要手机发中文名：**用 POST，把参数放正文里**（body 里原始中文安全），或用 App 的 URL 编码功能后再放 GET。

本仓库的极简 App（`android/`）已用 `URLEncoder` 处理，不受影响。

### 服务器的行为，理解了对排错很重要

- **同一个 `pkg` 重复上报不会产生新记录**，只刷新「在线」时间——所以定时器可以放心每 30 秒无脑上报。
- **90 秒内没收到任何请求 → 页面显示「离线」**。息屏后自动化被系统冻结是正常的，此时显示离线比显示旧应用更诚实。
- 每次「应用变化」都记入时间线，页面据此估算今日各应用时长。

## 2. 方案 A：MacroDroid（免代码，最轻量，约 5 分钟）✅ 推荐

只装一个免费 App，不写一行代码，不做任何编译。

**准备**：安装 MacroDroid（官网 `macrojdroid.com` 下载 APK，或应用商店）。首次打开授予它：
- **使用情况访问权限（Usage Access）** ← 检测前台应用必须
- 通知权限、忽略电池优化、自启动

**宏 1 —— 应用切换时上报**

1. 新建宏 → 触发器 → 分类「应用」→「应用启动 / App Launched」→ 选择「所有应用 / Any Application」。
   在触发器底部勾选「将应用信息保存到变量」（不同版本叫法略有差异），保存到一个变量，例如 `%app`。
2. 动作 → 分类「网络 / 连接」→「HTTP Post / HTTP Get」。
   - 方法：GET
   - URL（**只发包名，最稳**，中文名由服务器映射）：
     ```
     http://39.96.193.209:4173/api/report?t=6184f94a5eaa9fac6a0c3e7c&pkg=%app
     ```
   - **别手打占位符**：在 URL 输入框里长按 → 「插入占位符 / 变量」→ 分类「应用」→ 选「前台应用包名」，MacroDroid 会自动填成它自己认识的写法（如 `%pn`、`%app`）。版本不同名称不同，选出来的一定是对的。
   - 想让手机直接发应用名：别塞进 GET 的 URL（中文会 400，见 §1），改用「HTTP Post」把 `name=xxx` 放**正文**里。
3. 约束：留空。命名「上报当前应用」，保存。

**宏 2 —— 心跳（防离线误判）**

触发器「日期/时间 → 间隔执行」每 30 秒 → 动作复制宏 1 的 URL，但用「当前前台应用」占位符；息屏时可以不发。

**宏 3 —— 息屏/锁屏**

- 触发器「显示 → 屏幕关闭」→ 动作 URL：`...?t=<token>&screen=off`
- 触发器「显示 → 屏幕打开」→ 复用宏 1 的动作

**必做的保活**（否则后台被杀，页面很快显示离线）：
设置 → 应用管理 → MacroDroid → 电池 → **无限制**；打开**自启动**；MIUI 还要在「省电策略」里选「无限制」。

## 3. 方案 B：Tasker（已有 Tasker 的人）

1. 新建 **事件（Event）** → 类别「界面 / 应用程序（Display / App）」→「应用启动（Application Launched）」，应用留「任意（Any App）」。
2. 同一 Profile 下新建 **任务 → 动作 → 网络 → HTTP Post（HTTP Post / 436）**：
   - Server:Port：`39.96.193.209:4173`
   - Path：`/api/report`
   - Headers：`X-Token: 6184f94a5eaa9fac6a0c3e7c`
   - Body：`pkg=%pkg`（Tasker 的 HTTP Post 正文按 urlencoded 发送；中文名放正文是安全的，放 URL 会 400，见 §1）
   - 变量同样**长按 → 插入 → 从选择器里挑**「应用包名」（Tasker 常见为 `%pkg`，以选择器为准）。
3. 另加 Profile：事件「屏幕关闭（Screen Off, 212）」→ HTTP Post body `screen=off`。
4. 定时心跳用「任务 → 等待 30 分循环」或直接用「场景 → 前台应用」监控，嫌麻烦可省略——靠应用切换事件已够用，只是息屏后页面会走离线。

## 4. 方案 C：自带极简 App（源码在本仓库 `android/`，**已编译好的 APK 在 Releases**）

不想依赖第三方自动化 App、要真正实时且能后台常驻的话，用这个。约 300 行代码，无第三方库，权限只有**无障碍服务**（读前台应用）+ **网络**；v1.1 起再加一个可选的**使用情况访问权限**，用来在事件丢失时自愈。

### 直接装现成的（推荐，不用编译）

Releases 里有编译好的 `AppCast-Monitor-v1.1.apk`（约 600 KB，minSdk 24 / targetSdk 34，release 签名、非 debuggable）。仓库是私有的，所以下载前先登录 GitHub。

1. 下载 APK → 点击安装（提示未知来源时允许）。覆盖升级不必先卸载：v1.0 与 v1.1 用同一个签名密钥，可直接装。
2. 设置 → 无障碍 → 已下载的应用 → **AppCast Monitor** → 开启。
3. 建议再开一项：设置 → 安全 → **使用情况访问权限** → AppCast Monitor → 允许。不开也能跑，只是退回纯事件模式（见下方「v1.1 改了什么」）。
4. 打开 App，首页两行状态应显示「无障碍服务：已开启」「使用情况访问：已授予」；点「发一条测试上报」，看板应立刻出现「手动测试」。
5. 保活同方案 A：电池无限制 + 允许自启动，MIUI / ColorOS 还要在省电策略里选无限制。

### v1.1 改了什么（为什么不是「事件上报一次就完事」）

无障碍事件通道本身会丢事件：快速连切时系统会合并 `TYPE_WINDOW_STATE_CHANGED`（`notificationTimeout` 原来是 120ms），回调线程被 PackageManager 的查询堵住时通道溢出也会丢。丢掉的后果不是「少一条记录」，而是**看板一直显示上一个应用**——因为心跳重发的就是缓存里的 `lastPkg`，App 从不主动去查真正的前台是谁，错误值还会被每 45 秒一次的心跳续命，直到你下一次切换应用才纠正。

v1.1 起：每 10 秒用 `UsageStatsManager` 查一次真实前台包名做校准，不符就补报（事件负责零延迟，轮询负责自愈）；心跳 45s → 10s；息屏只发 `screen` 状态且失败重试 3 次；显示名移到工作线程解析并缓存；`notificationTimeout` 120ms → 20ms；上报失败不再静默丢弃。

### 要自己编译的话

需要 JDK 17+、Android SDK（`platforms;android-34` + `build-tools;34.0.0`）、Gradle 8.7 以上（实测 8.10 + AGP 8.5.2 + Kotlin 1.9.24 可过）。

- Android Studio：`File → Open` 选 `android/` 目录，同步后 `Build → Build APK(s)`，产物在 `app/build/outputs/apk/debug/`。
- 命令行 debug 包：`gradle assembleDebug`。
- 命令行 release 包（要签名，否则 `assembleRelease` 产物未签名、装不上）：
  ```sh
  keytool -genkeypair -keystore your.keystore -alias appcast -keyalg RSA -keysize 2048 -validity 10000
  gradle assembleRelease -PRELEASE_STORE_FILE=/绝对路径/your.keystore \
      -PRELEASE_STORE_PASSWORD=<口令> -PRELEASE_KEY_ALIAS=appcast -PRELEASE_KEY_PASSWORD=<口令>
  ```
  升级要保持同一把 keystore，签名变了就得先卸载再装。
- 换服务器或换 Token：改 `app/src/main/java/app/cast/monitor/Cfg.kt` 里的 `BASE` 与 `TOKEN` 后重新编译，这两值是编译期常量。
- 具体文件说明见 `android/README.md`。

## 5. 方案 D：手机已 Root / 用 ADB（极客向，最省事件延迟）

Root 后不需要任何权限，Termux 里跑：

```sh
TOKEN=6184f94a5eaa9fac6a0c3e7c
URL=http://39.96.193.209:4173/api/report
while :; do
  pkg=$(su -c 'dumpsys activity activities' | grep -m1 -oE 'mResumedActivity.*u0[0-9]*/[^ ]+' | sed 's#.*/##; s/^\([a-zA-Z0-9._]*\)/\1/')
  [ -n "$pkg" ] && curl -s "$URL?t=$TOKEN&pkg=$pkg" >/dev/null
  sleep 2
done
```

用 ADB 从电脑上观测（手机不用装任何东西，但得连电脑/或无线 ADB）：

```sh
adb shell dumpsys activity activities | grep -m1 mResumedActivity
```

## 7. 端口与安全组（已配好，供核对）

服务端已经跑在这台机器上（systemd 服务 `appcast`，已开机自启，监听 `0.0.0.0:4173`），本机 iptables 是放行策略，**4173/tcp 此前已在阿里云安全组放行过**，一般不用再动。若 §6 第 1 步在手机上连不通，再核对一次规则：

> 阿里云控制台 → ECS → 该实例 → 安全组 → 配置规则 → 入方向：
> 类型「自定义 TCP」，端口 `4173/4173`，源 `0.0.0.0/0`（或收紧成自己手机/家庭宽带的 IP），授权策略「允许」。

放行后在手机浏览器打开 §6 第 1 步那条链接验证。服务器侧常用命令：

```sh
systemctl status appcast              # 看服务在不在跑
journalctl -u appcast -f              # 看实时上报日志
systemctl restart appcast             # 改完 server/config.json 后生效
```

如果这台机器上还跑着 nginx（现在跑着，占用 80/443），更干净的做法是走 80 端口反代 + 域名 + HTTPS，协议参数完全不变，只是把 URL 换成 `https://你的域名/api/report?...`。配置样例见 `README.md` 的「对外访问」一节。

## 8. 隐私与安全须知（认真看）

- 这是**明文 HTTP**，Token 出现在 URL 里，链路上任何一跳都能读到，也会写进 nginx 访问日志。个人自用一般可接受；若你担心，优先上 HTTPS（见 README），并把 Token 改成请求头 `X-Token` 发送（服务器已支持）。
- **看板链接 = 谁拿到谁能看你正在用什么 App**。`?k=` 是访问口令，别外传、别截图带链接发群里。
- 服务器只保存每台设备最近 150 条切换记录（内存 + `data/state.json`），不上传第三方，不存原始请求体。
- 想彻底停某台设备：把它的 Token 从 `server/config.json` 里删掉或改掉，重启服务；上报会立刻 403。
- 建议改成自己手机上没有的东西，比如把 config 里的 `token` / `viewKey` 重新生成：
  ```sh
  node -e 'const c=require("crypto");console.log(c.randomBytes(12).toString("hex"),c.randomBytes(9).toString("base64url"))'
  ```

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 页面一直是「等待手机上报…」 | 手机没发出去：先做 §6 第 1 步定位是端口还是 Token |
| 几分钟后变「离线」 | 自动化 App 被后台杀了：电池无限制 + 自启动 + 锁后台；或加心跳宏 |
| 息屏后还显示最后一个应用 | 没配 `screen=off` 触发器（宏 3） |
| 显示的是 `com.xxx.yyy` 而不是中文名 | 映射表没这个应用：往 `server/config.json` 的 `labels` 里加一行再 `systemctl restart appcast`（比让手机发 `name` 可靠，见 §1「中文怎么发」） |
| 切换很快时偶尔漏一个应用 | 自动化 App 事件节流所致；无障碍方案 v1.1 起每 10 秒自愈（见 §4） |
| 无障碍 App 也会停在刚才那个应用上 | 系统把 `TYPE_WINDOW_STATE_CHANGED` 事件丢了。v1.0 只能等下次切换才纠正；v1.1 起靠 `UsageStatsManager` 校准，但**必须授予「使用情况访问权限」**，否则退回 v1.0 的行为 |
| 想加第二台设备（平板/备用机） | `config.json` 的 `devices` 数组里加一项（独立 `id`/`name`/`token`），重启即可，看板自动多一张卡片 |
| 上报返回 `{"ok":false,"error":"maintenance"}`（HTTP 503） | 服务器处于维护模式（服务器上 `data/maintenance` 存在）。这段时间的切换**不会补录**，维护结束、手机下一次切应用就恢复正常，MacroDroid 不用改 |
